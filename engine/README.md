# Pixel Wave 描画エンジン

名画のドット絵が、同心円の波で次々に入れ替わるアニメーションの描画エンジンです。
ブラウザの標準機能（TypeScript、Canvas 2D、Vite）だけで動き、フレームワークと
ランタイムの依存ライブラリは使いません。後でTauriアプリとmacOSの
スクリーンセーバー（WKWebView）に組み込む前提で、公開する関数は
`createEngine` だけに絞ってあります。

## 起動方法（確認用ページ）

```sh
npm install
npm run dev
```

ブラウザで表示されたURLを開くと、画面全体にエンジンが動きます。
既定では `assets/paintings/` の8枚（`credits.json` の一覧と切り抜き位置）を
使います。URLの引数で絵を指定することもできます。

```
http://localhost:5173/?images=a.jpg,b.jpg
```

## テストの実行方法

```sh
npm test          # Vitestの単体テスト
npm run typecheck # 型の確認
```

ドット絵化（切り抜き、縮小、k-means）と波の判定は `src/dotart.ts` の
純粋関数に分けてあり、`test/dotart.test.ts` でテストしています。
k-meansは乱数の種を引数で渡せるので、テストの結果は毎回同じです。

## ビルド

```sh
npm run build
```

- `dist/engine.js`：アプリから読み込むESモジュール（1ファイル）。
- `dist-demo/`：確認用ページのビルド結果（素材の画像を含む）。

## 公開する関数の使い方

```ts
import { createEngine } from "./engine.js";

const canvas = document.querySelector("canvas");
const engine = createEngine(canvas, [
  { id: "hokusai_great_wave", src: "assets/paintings/hokusai_great_wave.jpg" },
  { id: "klimt_the_kiss", src: "assets/paintings/klimt_the_kiss.jpg", crop: "top" },
]);

engine.start();        // 再生を始める
engine.stop();         // 止める（タイマーも止まる）
engine.setPaintings([  // 絵を入れ替える（再生は続ける）
  { id: "vangogh_starry_night", src: "assets/paintings/vangogh_starry_night.jpg" },
]);
engine.destroy();      // 破棄する
```

- `crop` は切り抜き位置（`"top"`、`"center"`、`"bottom"`）で、省略すると中央です。
- 絵はシャッフルして順に出し、全部出たらシャッフルし直します。同じ絵は続きません。
- 絵が1枚だけのときは切り替えず、0枚のときは背景色だけを表示します。
- 画像の読み込みに失敗した絵は飛ばし、理由をコンソールに出します。

## 動きと負荷

- 各画像は読み込み時に1回だけ、画面と同じ縦横比に切り抜いて
  1ドット12pxの解像度に縮小し、k-means法で16色に減らして保持します。
- 各ドットは12pxのマスに10pxで塗り、2pxの隙間を背景色（#141418）で残します。
- 1枚を14秒表示したら、画面の外周上の無作為な1点から円が広がり、
  10秒かけて一番遠い角まで届きます（イージングは
  cubic-bezier(0.37, 0, 0.63, 1) 相当で、ゆっくり始まりゆっくり終わる）。ドットの中心が円に
  入ると次の絵に替わり、先頭の帯（1.5ドット分）にあるドットは
  白に60%寄せて光る輪になります。
- 切り替え中だけ requestAnimationFrame で描き、描き直すのは
  そのフレームで状態が変わったドットだけです。表示中の14秒間は
  タイマー以外何もしません。
- `document.hidden` の間は自動で止まり、戻ると続きから再開します。
- 画面サイズが変わったら、新しい格子でドット絵化からやり直します。

## 値を決めた理由

- **12px**：1920×1080で160×90ドットになります。24px、16px、12px、8pxを
  試しました。8pxは溝の割合が25%になって網目が絵より目立ち、ドット絵化も
  約4秒かかりました。そのため12pxにしました（ドット絵化は約2秒）。
- **16色**：元になった大学の課題の仕様に合わせた数です。名画の
  色の階調を残すには足り、ドット絵らしい平らな色面も保てます。
  保持するデータも1枚あたり最大で160×90ドット分しかありません。
- **14秒**：1枚を「絵として眺める」には短すぎず、壁紙として
  眺めている間に必ず数枚が替わる長さです。切り替えの10秒と合わせて
  24秒で一巡する周期になります。
- **10秒**：最初は6秒で、減速のイージングを使っていました。しかし、
  最初の1～2秒で画面のほとんどが替わり、切り替わりが速すぎました。
  そのため10秒にし、ゆっくり始まりゆっくり終わるイージングに変えました。
