# Pixel Wave（アプリ本体）

利用者向けのダウンロードと入れ方は、リポジトリ先頭の
`README.md` にあります。要点だけ書くと、Windowsはインストーラー
実行時にSmartScreenで「詳細情報」→「実行」、macOSは初回起動時に
「システム設定」→「プライバシーとセキュリティ」で「このまま開く」、
LinuxのAppImageは実行権限を付けてから実行します。

名画のドット絵を壁紙とスクリーンセーバーで表示するTauri 2の
デスクトップアプリです。描画は前に作ったエンジン（`createEngine`）を
組み込んでいます（`src/engine.ts` と `src/dotart.ts` はエンジンの
プロジェクトから写したものです）。
今回の対象はWindowsで、OSごとの処理は
`src-tauri/src/platform/windows.rs` に分け、macOSとLinuxでも
ビルドが通る形にしてあります。

## 開発時の起動方法

必要なもの：Node.js、Rust（rustup）

```sh
npm install
npm run dev     # Tauriとして起動（画面の確認は npm run dev:vite でも可）
```

## ビルド方法

```sh
npm run build   # 画面のビルドとTauriのビルド（WindowsではNSISのインストーラー）
```

Rustの単体テスト（引数の読み取りと設定ファイルの読み書き）は
次で実行します。

```sh
cd src-tauri
cargo test
```

## 画面

設定ウィンドウは1つだけです。

- 上段のプレビューではエンジンが実際に動きます。チェックを変えると
  すぐ反映されます。
- 絵の一覧は素材の8枚が初期設定で全てオンです。「＋」か
  ドラッグ＆ドロップで画像（JPEG・PNG・WebP）を追加でき、追加した
  画像はアプリのデータフォルダ（`user-images/`）へ写されます。
  追加した画像にだけ削除ボタンが付きます。チェックは最低1枚必要で、
  最後の1枚は外せません。
- 「壁紙にする」が一番目立つボタンです。「スクリーンセーバーにする」で
  登録と設定画面の表示をします。
- 設定は変更した時点で `settings.json` に保存されます（保存ボタンは
  ありません）。設定画面を閉じてもアプリは終了せず、通知領域に
  常駐します（メニューは「設定」と「終了」だけ）。

## 壁紙の仕組み（Windows）

- ディスプレイごとに枠なしのウィンドウを作り、Progmanへ
  メッセージ `0x052C` を送って WorkerW を作らせ、その子ウィンドウに
  します（Lively Wallpaper と同じ方法）。これでデスクトップの
  アイコンより奥に表示されます。Windows 11 24H2 で構造が変わった
  場合に備え、`0x052C` は引数の組み合わせを2通り送り、アイコンを
  持つウィンドウ（SHELLDLL_DefView）の後ろにある WorkerW を探します。
- 壁紙ウィンドウはマウスの操作を受け取らず、タスクバーと
  Alt+Tab に出ません。
- 前面のアプリが全画面のときと、電池で動いているときは、Rust側の
  見張りスレッドが2秒ごとに判定し、エンジンを止めます。条件が
  外れたら再開します。
- 「壁紙を止める」かアプリの終了でウィンドウを片付けるので、
  元の壁紙がそのまま戻ります（システムの壁紙設定自体は変えていません）。
- 壁紙がオンの間は `tauri-plugin-autostart` でPC起動時に自動起動し、
  オフにすると解除されます。再起動後も壁紙がオンなら壁紙を出し直します。

## スクリーンセーバーの仕組み（Windows）

同じ実行ファイルを `.scr` として使います。起動時の引数で動きが
変わります（読み取りは `src-tauri/src/args.rs`、単体テストつき）。

- `/s`：全ディスプレイに全画面でエンジンを表示します。マウスの
  移動（数ピクセルの揺れは無視）、クリック、キー入力で終了します。
- `/c`（引数なしも同じ）：設定画面を開きます。
- `/p <HWND>`：プレビューは作らず、すぐ終了します。

「スクリーンセーバーにする」を押すと、実行ファイルをアプリの
データフォルダへ `PixelWave.scr` として写し、
`HKCU\Control Panel\Desktop` の `SCRNSAVE.EXE` にその場所を
設定して、Windowsのスクリーンセーバー設定画面
（`control desk.cpl,,@screensaver`）を開きます。
管理者権限は使いません。

## 設定ファイル

アプリのデータフォルダに `settings.json` を1つ置き、壁紙と
スクリーンセーバーが同じファイルを読みます。

```json
{ "enabled": ["hokusai_great_wave", "user_ab12"], "userImages": [{ "id": "user_ab12", "file": "user_ab12.jpg", "title": "元のファイル名" }], "wallpaper": true }
```

読めないとき（無い、壊れている）は初期設定で動き、壊れたファイルは
`settings.broken.json` に退避します（`src-tauri/src/settings.rs`、
単体テストつき）。

## macOS版

OSごとの処理は `src-tauri/src/platform/macos.rs` にあります。
Windows版の動きは変えていません。

### ビルド方法（Mac上）

```sh
scripts/build-macos.sh
```

エンジン、セーバー（`saver/build.sh`、Xcodeを使わず `swiftc` で
組み立て）、アプリのユニバーサルバイナリ（Apple SiliconとIntelの両対応）の
順に作り、最後にアプリと `.saver` を入れた `PixelWave-macOS.dmg` を
作ります。署名はアドホック署名（`codesign --force --deep -s -`）だけで、
Apple Developer Programには入りません。セーバーをアプリの資源として
取り込むため、セーバーを先に作る順番が必須です。

### 壁紙（macOS）

- ディスプレイごとに枠なしのウィンドウを作り、階層を
  `kCGDesktopWindowLevel` にしてアイコンより奥に置きます
  （Plashと同じ方法）。`collectionBehavior` に `canJoinAllSpaces`・
  `stationary`・`ignoresCycle` を付け、全てのSpacesに出し、
  Mission Controlでは動かないようにします。マウスの操作は
  受け取りません。
- 前面のアプリが全画面のときと、電池で動いているときはエンジンを
  止めます。全画面の判定は前面のウィンドウが画面全体を占めるかで、
  電池の判定はIOKitの `IOPSCopyPowerSourcesInfo` です。
- Dockにアイコンは出さず、メニューバーにだけアイコンを置きます
  （メニューは「設定」と「終了」）。自動起動はWindows版と同じ
  `tauri-plugin-autostart` です。

### スクリーンセーバー（macOS）

- Swiftの `.saver` バンドル（`saver/`）で、`ScreenSaverView` の中で
  `WKWebView` を動かし、描画エンジンを表示します。Web一式は
  独自スキーム `pixelwave` で渡すため、モジュールの読み込みが
  ファイルの制限に触れません。
- 設定の共有方法：他社製セーバーは `legacyScreenSaver` の
  サンドボックスの中で動き、アプリのデータフォルダを読めません。
  候補のうち、バンドルへ設定を書き込んでから入れる方法は、設定を
  変えるたびに入れ直しと再署名が必要になります。もう一方の
  「サンドボックスの中から読める場所へアプリが書き出す」方法は、
  `~/Library/Application Support/` がサンドボックスの中から
  読み取りできることが実測で知られており、設定変更がそのまま
  反映されます。そこで後者を選びました。アプリは設定を変えるたびと
  登録時に、`~/Library/Application Support/PixelWave/` へ
  `saver-settings.json` と使う絵（`images/`）を書き出します。
  セーバーは本当のホームを `getpwuid` で取り（サンドボックスの中では
  `NSHomeDirectory()` がコンテナを指すため）、そこから読みます。
  書き出しが無いときは、バンドルの初期設定（素材8枚）で動きます。
- 「スクリーンセーバーにする」を押すと、`.saver` を
  `~/Library/Screen Savers/` へ写し、システム設定のスクリーン
  セーバーの画面を開きます。macOS 14以降は選んだセーバーが
  保持される場所に公開APIが無いため、選択は利用者が画面で
  行います（一覧の下の方の「その他」にあります）。
- macOS 14以降の既知の問題への対策：セーバー終了時に
  `stopAnimation` が呼ばれず処理が裏に残るため、分散通知
  `com.apple.screensaver.willstop` を受けたらその実例を無力化して
  `WKWebView` を片付けます。プロセスごと終了させる方法は、
  すぐに再起動したときに黒画面になる競合があるため使いません。

### 利用者向け：Gatekeeperの許可の手順

公証を受けていないため、初回の起動はGatekeeperに止められます。

- macOS 15以降：「システム設定」→「プライバシーとセキュリティ」を
  開き、下の方にある「このまま開く」を押します。
- それ以前：アプリを右クリック（またはControlを押しながらクリック）
  して「開く」を選び、確認の画面でもう一度「開く」を押します。

一度許可すれば、次からは普通に起動できます。

## Linux版

- 壁紙とスクリーンセーバーは作らず、全画面表示だけにします
  （WaylandとX11で同じ動きにするため）。設定画面のボタンは
  「全画面で表示」の1つだけになり（OSの判定はRust側の
  `get_platform` コマンド）、キー入力かクリックで終わります。
  終わると設定画面のボタンの表示も戻ります（Rust側からの通知で
  同期します）。
- 電池で動いているときはエンジンを止めます。判定は
  `/sys/class/power_supply/` の電池の有無と交流電源の `online`
  です（`src-tauri/src/platform/linux.rs`）。
- 常駐アイコンは出せる環境でだけ使います。出せない環境
  （GNOMEの初期状態など）では、設定画面を閉じたらアプリが
  終了するようにし、設定画面から全ての操作ができるように
  しています。再起動後に全画面表示が自動で開くことはありません。
- 配布は `.AppImage` と `.deb` です（GitHub Actionsの
  `release.yml`）。
